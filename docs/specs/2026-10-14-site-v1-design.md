# arkeep.io v1: marketing site + docs skeleton

Date: 2026-10-14 · Status: approved in conversation, pending spec review

## 1. Goal

One Astro repository serving two things:

- **Marketing site** at `/` (and future top-level routes such as `/roadmap`): sells what Arkeep does today (self-hosted, centralized backups on Restic and Rclone) and shows where it is going.
- **Documentation** at `/docs/*`, built with Starlight.

English only, routes included. No Italian anywhere, same as the product.

Success for v1:

- The homepage is complete, with all three interactive pieces working (hero backup/break/restore, retention preview, pinned agents fragment), in light and dark, at 1440, 768 and 390 px.
- Six real docs pages, migrated from the arkeep README.
- `astro build` passes, with no broken internal links.
- taste-skill `lint.mjs` and `inspect.mjs` pass with zero FAIL.
- A `web-design-guidelines` review is done and its findings addressed.

Composition and bans come from taste-skill: no gradient wash, eyebrows, pill badges, icon-topped card rows, shadows at rest, glass nav, thin rules outside `data-ui` fragments. `DESIGN.md` gets updated at the end to match. |

| Output | Static, `site: 'https://arkeep.io'`, sitemap. Host not chosen yet; no adapter. |
| Screenshots | Generated by a Playwright script from a locally running Arkeep with demo data. Fictional admin "Alex Rivera"; no real personal data. |
| Commits | Claude does not commit; the user does. |

### Deviations from the direction sheet

- **Navigation:** the sheet asks for no navigation bar. We keep a minimal plain bar (wordmark, Docs, Roadmap, GitHub, one action) because the docs need an entry point.
- **CTA:** "Sentence with a blank" uses a platform `<select>` instead of an email field, since there is no form backend.
- **List section:** "Day tabs, banded agenda" becomes the roadmap, with one tab per version.
- **Imagery:** the sheet says "no screenshots". We use real Playwright screenshots as the image floor (cropped interface fragments, `data-ui`), plus HTML fragments for the interactive pieces. No device or browser frames.

### 4.3 Interactive pieces

All pieces are built in HTML with `data-ui` roots, use product radii and borders inside, and work by keyboard and thumb.

**Hero backup fragment** (the live thing)
- **Policy card:** `arkeep.io`, sources = the page's sections, two destinations ("NAS (local)", "Backblaze B2").
- **[Run now]:** streams log lines, with a file list and byte counts measured from the live DOM (`outerHTML` length per section). Ends with `snapshot a3f9c1d2 saved` (ID derived from a hash of the content), "Succeeded" status and duration.
- **[Break something]:** removes one section (its content is replaced by a "missing" state that keeps its layout height, to avoid a jump).
- **[Restore]:** puts it back from the snapshot. Both states are announced via `aria-live`.
- **Reduced motion:** the log appears without typing animation.
- **No JS:** static completed job.

**Retention preview** (showcase)
- 30-day timeline of snapshots (one every 6 hours, 120 dots).
- Controls: keep last / hourly / daily / weekly / monthly (number steppers), destination switch (NAS, Backblaze B2, SFTP offsite) with independent retention per destination, matching the product's per-destination retention.
- Applies restic `forget` bucket semantics (newest snapshot per bucket, keep-last first) client-side. Kept vs forgotten is shown by fill, not colour alone. A count readout reads "Keeps 23 of 120 snapshots".
- On a phone, only the four most telling controls are shown, plus a link that reveals the rest.

**Pinned agents fragment** (how it works)
- Sticky stage holding an Agents table in three states (empty with an enrollment command / one agent connecting → online / four agents online with one job running). State follows the statement nearest the viewport centre (IntersectionObserver).
- Inactive statements stay at full-strength muted ink, not faded.
- Phone: the stage is sticky at the top at 46svh.
- No JS: all three states rendered in sequence.

### 4.4 Motion

- **Signature:** masked line reveal on the hero h1 (two lines, 110 ms apart).
- **Section entrances:** heading → text → picture, 60–90 ms stagger, 16–32 px rise, once.
- **Feedback:** on every control.
- **Moving picture:** a short muted loop recorded by the screenshots script (a job log streaming in the real GUI), used in the features grid with a poster frame.
- Transform and opacity only. A `prefers-reduced-motion` fallback for everything. Content is never hidden if JS fails.

## 6. Screenshots pipeline

`scripts/screenshots/` (Node + Playwright, dev dependency):

1. Expects a local Arkeep running from `../arkeep` (`task run:dev` + `task run:agent`; documented in a README next to the script, not started by the script).
2. Completes setup with admin "Alex Rivera" (`alex@example.com`) inside the 15-minute setup window.
3. Creates demo data through the REST API: local destinations under a temp dir, policies with Docker/paths/command sources where available, and triggers real jobs. Agents: the real local agent(s), never fabricated counts.
4. Captures the light and dark themes at 2x for: dashboard, agents, policy editor, job log, snapshot browser, notification settings, security (2FA/OIDC). The output goes to `src/assets/screens/<name>-<theme>.png` and is served through `astro:assets` (AVIF/WebP).
5. Theme-aware `<picture>` swap on the page.
