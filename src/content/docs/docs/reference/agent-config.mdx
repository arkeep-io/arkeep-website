Every option can be set with a flag or an environment variable. When both are set, the flag wins.

| Flag | Environment | Default | Description |
|---|---|---|---|
| `--server-addr` | `ARKEEP_SERVER_ADDR` | `localhost:9090` | Server gRPC address, as `host:port` with no scheme |
| `--agent-secret` | `ARKEEP_AGENT_SECRET` | | Shared secret; must match the server's |
| `--state-dir` | `ARKEEP_STATE_DIR` | `~/.arkeep` | Agent state, certificates, the extracted restic and rclone binaries and the [restic cache](#restic-cache) |
| `--server-http-addr` | `ARKEEP_SERVER_HTTP_ADDR` | `--server-addr` host, port 8080, plain HTTP | Base URL of the server's HTTP API, used once for enrollment. **Required when the server is behind a TLS-terminating reverse proxy**, for example `https://arkeep.example.com`. |
| `--grpc-tls-ca` | `ARKEEP_GRPC_TLS_CA` | | CA certificate for gRPC TLS, only when the server uses its own certificate signed by a CA the system does not trust |
| `--grpc-insecure` | `ARKEEP_GRPC_INSECURE` | `false` | Disable TLS for gRPC. Same machine or trusted private network only. |
| `--docker-socket` | `ARKEEP_DOCKER_SOCKET` | platform default | Docker socket path |
| `--docker-host-root` | `ARKEEP_DOCKER_HOST_ROOT` | `/hostfs` inside Docker, empty otherwise | Where the host filesystem is mounted inside the agent container. Set it only for a custom mount point. |
| `--allow-ephemeral-local-destination` | `ARKEEP_ALLOW_EPHEMERAL_LOCAL_DESTINATION` | `false` | In a container, back up to a local destination even when it is not on a bind mount or a volume. Its repository is lost when the container is recreated: tests only. See [Local destinations in Docker](/docs/installation/docker-compose/#local-destinations-in-docker). |
| `--hostname` | `ARKEEP_AGENT_HOSTNAME` | the host's hostname | Name reported to the server and recorded on snapshots. Inside Docker it is read from the host's `/etc/hostname` through the host mount. |
| `--log-level` | `ARKEEP_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |

## Enrollment

On first start the agent generates its private key, sends a certificate request to
`<server-http-addr>/api/v1/agents/enroll` with a proof of the agent secret, and stores the CA certificate
and its client certificate in `--state-dir`. Later starts reuse them. Delete them to enroll again (an admin
may then need to [reset the agent's identity](/docs/guides/agents/#reset-identity)).

The secret itself is never sent, and the agent accepts the server's answer only with the server's proof of
the same secret, so plain HTTP is safe for enrollment. An agent refuses a server older than itself and logs
*the answer does not prove that the server knows the agent secret*: upgrade the server first.

## Embedded tools

The agent binary embeds restic and rclone and extracts them into `--state-dir` at startup. Nothing else needs
to be installed on the machine, except the tools your [command sources](/docs/guides/databases/) and hooks call.

## Restic cache

restic keeps a local copy of each repository's metadata (index, snapshot list, directory trees), so that a
backup, a retention run or a snapshot browse does not download it again from the destination. The agent keeps
this cache in `<state-dir>/cache`. In Docker, the state directory is a volume, so the cache survives image
updates and container recreates.

The cache holds metadata only, not file contents: it speeds up remote destinations, especially over slow or
high-latency links, but restores still read file data from the destination. Its size grows with the number of
files and snapshots, from a few megabytes to a few gigabytes. Retention runs delete the cache of a repository
the agent has not used for 30 days.

To keep the cache elsewhere, for example on a faster disk, set `RESTIC_CACHE_DIR` (or `XDG_CACHE_HOME`) in the
agent's environment: the agent then leaves the location to restic.

## Permissions

The agent runs as an unprivileged user. It only needs to read what it backs up and to write where it restores.
To back up Docker volumes it must read `/var/lib/docker/volumes`, which usually means membership of the
`docker` group (the Docker Compose deployment handles this through its mounts).
