---
title: Importing and syncing snapshots
description: Bring existing restic repositories into Arkeep, and keep Arkeep's snapshot list in step with the repositories.
---

## Import an existing repository

If a location already holds a restic repository, for example from before you used Arkeep, Arkeep can list
its snapshots so you can browse and restore them.

**When creating a destination:** turn on **Import existing repository**, choose an **Agent** that can reach
the repository and enter its **Repository Password**. Arkeep tests the repository through that agent before
saving the destination. If the agent is offline, the password is wrong or restic reports an error, nothing
is saved and the error is shown.

**On an existing destination:** use **Import snapshots** from the Destinations list, with the same two
fields.

The password is stored, encrypted, on the destination: it shows the **Existing repo** badge, and new
policies can reuse the password with **Use the destination's existing password**.

The result tells you what happened: *N snapshots imported*, *Already up to date*, *Repository is empty* or
*N could not be imported*.

Imported snapshots have no policy and no job. They can be browsed and restored, and retention never forgets
them, because Arkeep only sweeps snapshots that belong to its own policies.

## Sync snapshots

Arkeep keeps its own list of snapshots and reconciles it with the repository after every backup and every
retention sweep. Snapshots can also change outside Arkeep, for instance when an append-only rest-server
runs `restic forget --prune` from its own cron job.

To pick those changes up without waiting:

- **Sync Snapshots** on a destination's page syncs that destination;
- **Sync Destination** or **Sync All** on the Snapshots page syncs the filtered destination or every
  enabled one.

The repository is the source of truth: snapshots no longer in it are removed from the list, and snapshots
Arkeep has never seen are added as imported. The result reads, for example, *Sync complete — 2 snapshots
removed, 1 snapshot added. 48 snapshots in the repository.*, or *Already up to date — 48 snapshots in the
repository.* when nothing changed.

The repository is read, never locked, by an online agent: the destination's maintenance agent if it is
connected, otherwise the agent of any policy writing there. A sync is refused when:

- no such agent is online;
- a backup, retention sweep or integrity check is running on the destination (try again when it finishes);
- the destination's repository password is unknown (import its snapshots once to store it).

### Periodic sync

Set **Sync every (hours)** in **Settings → Snapshot Sync** to sync every enabled destination on a schedule.
It is off by default (0), and accepts up to 720 hours.
