## Prerequisites

| Tool | Version | Install |
|---|---|---|
| Go | 1.27+ | [go.dev](https://go.dev/dl/) |
| Node.js | 26 (as in CI) | [nodejs.org](https://nodejs.org/) |
| pnpm | 12 (pinned in `gui/package.json`) | `npm install -g pnpm` |
| Docker | any | [docker.com](https://www.docker.com/) |
| protoc | 29.3 (as in CI) | [GitHub releases](https://github.com/protocolbuffers/protobuf/releases/tag/v29.3) |
| Task, protoc-gen-go, protoc-gen-go-grpc, govulncheck, gosec | pinned in `tools/go.mod` | `cd tools && GOWORK=off go install tool` |

Every tool is pinned ([ADR 0013](https://github.com/arkeep-io/arkeep/blob/main/docs/adr/0013-pin-and-verify-every-dependency.md)).
Go follows the `toolchain` in `go.work` and downloads it on its own. After the first install,
`task tools:install` keeps the Go tools in sync with `tools/go.mod`.

Node.js 25 and later no longer ship Corepack, so install pnpm directly; it switches to the version pinned by
`packageManager` in `gui/package.json` on its own.

## Getting started

```bash
git clone https://github.com/arkeep-io/arkeep
cd arkeep

# Download the restic and rclone binaries embedded into the agent at build time
task deps:download

# Generate gRPC code from the .proto definitions
task proto

# Terminal 1: the server (http://localhost:8080, gRPC :9090)
task run:server

# Terminal 2: the web interface dev server with hot reload (http://localhost:5173)
task run:gui

# Terminal 3: an agent connected to the local server
task run:agent
```

`task run:dev` starts the server and the interface together in one terminal; the agent still runs on its own.

The interface dev server proxies API requests to the server, so frontend and backend both reload as you
work. In production the interface is compiled and embedded in the server binary; no separate web server is
needed.

`task run:server` sets development secrets and turns telemetry off:

```text
ARKEEP_SECRET_KEY=dev-secret-key-00000000000000000
ARKEEP_AGENT_SECRET=dev-agent-secret
ARKEEP_TELEMETRY=false
```

### First login

Open the interface's dev server at `http://localhost:5173` (port 8080 serves the interface only after
`task build:server`). The first visit redirects to the setup page, where you create the admin
account. It only accepts the account within 15 minutes of the server starting; restart the server if the
window has passed.

## Tasks

```bash
task build          # Build all binaries (server + agent, interface included)
task build:server   # Build the server (builds the interface first, then embeds it)
task build:agent    # Build the agent (downloads restic and rclone first)
task build:gui      # Build the interface only (gui/dist/), with vue-tsc type checking
task test           # Run all tests (shared, server, agent, interface)
task lint           # Run golangci-lint on the server module
task proto          # Regenerate gRPC code
task tidy           # Tidy all Go modules
task clean          # Remove build artifacts

task run:server     # Run the server in development mode
task run:agent      # Run the agent in development mode
task run:gui        # Run the interface dev server with hot reload
task run:dev        # Run the server and the interface together

task deps:download  # Download restic and rclone for the current platform
task tools:install  # Install the pinned Go tools from tools/go.mod
task deps:pins:check  # Fail if a dependency is not pinned (ADR 0013)
```

## Tests

```bash
task test           # all Go modules and the interface
task test:shared    # shared only
task test:server    # server only
task test:agent     # agent only
task test:gui       # interface only
```

The three Go modules are separate, so run a single test from inside its module:

```bash
cd server && go test -v -run TestAgentHandler_List   ./internal/api/
cd agent  && go test -v -run TestResolveSources      ./internal/executor/
```

Go tests are table-driven with the standard `testing` package and live next to the code they test.
`server/internal/integration/` runs a real server and gRPC listener in-process against an in-memory SQLite
database, with no restic binary or Docker needed.

Interface tests use Vitest with Vue Test Utils and jsdom, and also live next to the code they test
(`Foo.test.ts` alongside `Foo.vue`). Every form has one, covering its validation and the request it sends;
`gui/src/test/mount.ts` mounts a page with its store and router. Run a single file from `gui/`:

```bash
cd gui && pnpm vitest run src/pages/settings/SMTPPage.test.ts
```

Forms are validated with vee-validate and zod, as described in
[CONTRIBUTING.md](https://github.com/arkeep-io/arkeep/blob/main/CONTRIBUTING.md#forms).

CI runs every Go module's tests with the race detector, `golangci-lint` on each module (locally `task lint`
covers the server only), the build of the agent for armv7, MIPS and MIPSLE, and the interface build with type
checking followed by its tests.
